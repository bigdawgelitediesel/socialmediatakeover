## Part 2. The three sound tools, vetted for our stack

Our stack: Windows 11, CPU only, Python 3.12, Node 24, ffmpeg 9, Remotion 4. Our assets: `words.json` (word timings), an EDL with cut frames, and a Remotion props JSON with overlay start frames. Nothing was installed; everything below is from READMEs, pyproject files, API probes and the repos' metadata on 2026-11-21.

### 2.1 Earshot

- **What it is**: `github.com/Leonxlnx/earshot`, author Leon Lin. A Python package, CLI, MCP server and Claude Code plugin that **synthesises sound effects from a text request, in code, on the CPU, with no audio model**. Created 2026-10-15, **v1.0.0 released 2026-11-20**, 5,431 stars, 378 forks. Site: leonxlnx.github.io/earshot-site. Not on PyPI (the name belongs to another project), installs from git.
- **Licence**: MIT for the code; rendered sounds are yours for any use, no credit; the learned ("resyn") sounds come from public-domain recordings credited in CREDITS.md; the optional listening models download under their own licences (CLAP Apache-2.0, AST BSD-3-Clause).
- **What it contains**: `make "a soft success sound" -o x.wav` (no model, a few seconds); a **bank of 252 sound effects stored as code** (183 forge-made, 51 made for music-led launch films such as `cut_hit/sub`, `whoosh/sweep`, `rise/breath`, `shutter`, `reverse_swell`, 3 kalimba voices, 15 fitted from CC0 recordings) under `earshot sfx list|render|check`; a catalogue of 922 designs in 384 families; `build` and recipes (layer catalogue parts into a new sound, JSON an agent can edit); `forge` (search for a sound by listening to its own takes, needs the listen extra); `fit` (turn a recording into code); **`kit init --preset calm|crisp|minimal|launch` and `kit render`** (one sound per role, cached takes, a `kit.lock.json` with each take's measured onset, peak and end; the launch preset sets each role's level over the music and its place against the cut); `pack` (a howler.js sprite); and the **listening side** (`describe`, `match`, `find`, `compare`, `realness`, **`timeline FILE --video V --cues C`** which reports events with time, level and tag and checks sync against picture cuts and cues, `sheet` for an annotated image, `critique`, `measure` for LUFS/true peak without models). Every file prints its result line: design, length, `peak at`, LUFS, clean/warnings. Output 48 kHz stereo (or `--mono`), wav/flac native, ogg/mp3/m4a/webm through ffmpeg; one-shots peak at -1 dBFS true peak and no louder than -14 LUFS momentary.
- **Requirements**: Python 3.10+ (3.12 is in the classifiers). Base deps numpy, scipy, soundfile, soxr, numba (about 350 MB). ffmpeg only for compressed formats and reading video. The `listen` extra adds torch (CPU wheel), transformers, librosa and downloads about 1.1 GB of models (2.2 GB on disk) on first use; each listen CLI call loads models for 20 to 40 s (the MCP server keeps them warm). **No GPU. No API key** (the `llm` extra for a Gemini critique is optional and uses your own key).
- **Windows install (do not run yet)**:
  ```
  py -3.12 -m venv C:\tools\earshot\.venv
  C:\tools\earshot\.venv\Scripts\python -m pip install "earshot @ git+https://github.com/Leonxlnx/earshot"
  :: later, if we want the listening side:
  C:\tools\earshot\.venv\Scripts\python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
  C:\tools\earshot\.venv\Scripts\python -m pip install "earshot[listen,measure,images,mcp] @ git+https://github.com/Leonxlnx/earshot"
  C:\tools\earshot\.venv\Scripts\python -m earshot doctor
  :: MCP for Claude Code (optional): claude mcp add earshot --scope user -e EARSHOT_THREADS=3 -- C:\tools\earshot\.venv\Scripts\earshot mcp
  ```
  The README's only Windows note is the `.venv/Scripts/python` path. numba ships Python 3.12 wheels, so no compiler needed.
- **How it plugs into our pipeline**: (1) render one El Coyote kit once (`kit init --preset launch`, then swap roles for our taste), giving `whoosh`, `hit`, `tick`, `riser`, `click`, `sting` wavs plus the lock file with `peak` per take; (2) our own `place_sfx.py` reads the EDL cut frames and the props overlay start frames, converts to seconds at our fps, and starts each file at `t_cut - peak_s` so the loudest sample lands on the cut (this is exactly what the earshot site describes: a cut at 12.00 s, file starts at 11.96 s); (3) mix under the voice with ffmpeg `sidechaincompress` or a fixed -12 dB duck during speech windows from `words.json`; (4) later, `earshot timeline mix.wav --video reel.mp4 --cues cues.json` as a sync audit.
- **Judgment**: **worth installing, base extra only.** It solves the "UI click sounds" gap with licence-clean, infinitely re-rollable sounds and gives us measured peaks, which is what frame-accurate placement needs. Skip `listen` until the base pays off; 2.2 GB of models and 30-second startups are a lot for a one-man workflow. Synthesised sounds read as "UI", so for a diesel account use them for interface beats (counters, cards, ticks) and keep real recordings (engine, air tools, shop) for the physical world.
- **Alternatives**: **julienaxyomlabs/reel-sfx** (MIT code, **CC0 audio**, 19 procedural whooshes/risers/impacts/pops/clicks, NumPy only, created 2026-10-30, 0 stars; `reel_sfx.place([{"frame": 45, "id": "whoosh.air"}], duration=10, fps=30)` lands each sound's anchor sample-accurately and `mix(voice, stem, duck_db=6)` ducks under dialogue; the smallest thing that does our job, one `pip install git+...@v0.1.0`). **ElevenLabs Sound Effects API** (100 credits per generation at auto duration, 11 credits per second when you set a duration, 30 s max; the free 10K-credit tier is non-commercial and the pay-as-you-go page says the SFX API is disabled on free, so budget the $5 Starter plan; the only option here for "a 7.3 turbo spooling then a wastegate flutter"). **Stable Audio Open Small** (341M params, Stability AI Community Licence, free under $1M revenue, Arm-CPU optimised; runs through stable-audio-tools on x86 CPU but no benchmarks exist for that and the original Stable Audio Open 1.0 is research-only, so treat it as an experiment, not a tool). Meta AudioGen weights are CC-BY-NC, out for sponsor content.

### 2.2 RealSFX (Clipwing "real-sfx")

- **What it is**: a **Claude Code skill**, folder `skills/real-sfx` in `github.com/Clipwing/skills` (repo created 2026-10-09, pushed 2026-11-11, 160 stars; the other skill is "HyperFrames to After Effects"). Published by Clipwing (clipwing.pro, a paid editing service; catalogue at clipwing.pro/skills). A SKILL.md plus a set of Python scripts, references, evals, tests and a vendored UI-sound package. It **does not synthesise**: it places **real recorded sounds from your own library** on the exact frame, keeps music and voice, removes a synthesised layer baked into the render instead of doubling it, and returns a new MP4, a separate SFX WAV, a cue report and a self-critique scoreboard. The SKILL.md triggers are in English and Russian.
- **Licence**: scripts MIT; the bundled `uisfx` code MIT and its **78 UI sounds CC0**; your own libraries keep their licences (the skill only reads them). No repo-level LICENSE file is set on GitHub, the MIT statement is in the README.
- **How it finds moments, best to worst** (from SKILL.md): (1) the project's own typed event list `docs/cues.json` or a synthesiser script `audio.cjs` whose `whoosh(4.2)` calls become cues, via `from_cues.py`; (2) a screen recording, region by region, via `ui_events.py`; (3) a HyperFrames composition's `data-start` timeline via `from_hyperframes.py`; (4) picture only via `find_moments.py` (kinds `cut`, `burst`, `onset`, `settle`; `--fine` adds chroma changes for soft animation). Its own numbers on (4): brightness alone finds 13 to 25 percent of the events a human lists on soft coloured animation, `--fine` 33 to 69 percent, so **the "scan" is a draft, the cue list is the real input**. `beats.py` builds a beat grid checked against the kick band (<125 Hz) and `mix.py --snap-beats` snaps within 50 ms. `mix.py` flags: `--plan`, `--voice-safe` (depths light/normal/deep), `--duck`, `--target-lufs`, `--masking` (needs the skill's venv), `--music-ref` for tuning tonal sounds to the score's notes. Then `critique.py` (axes include `doubling` and `match`), `levels.py`, `texture.py` (small sounds in the holes of SFX-only films), `bed.py` (one long real recording under the film), `listen_page.py` (blind A/B pages for human ears, `serve --lan` for phones).
- **Cue format**: a JSON list of typed events in seconds, e.g. `{"t":19.99,"type":"typing","len":0.36,"n":99}`; kinds named in the docs: whoosh, wipe, click, key, coins, pop, bell, chime, tick, glass, bead (any unknown kind can be mapped with `--kind bead=click` or `--map '{"glass":{"ids":[65,54],"role":"chime"}}'`). Events of one kind within 25 ms fuse; runs faster than 14 per second are thinned; a run of 8+ clicks 35 to 170 ms apart is recognised as typing.
- **Requirements**: Python 3.9+, **ffmpeg with ffprobe in PATH and with the `drawtext` and `rubberband` filters** (the frame sheets and pitch shifts use them; the Windows `Gyan.FFmpeg` full build has both, our ffmpeg 9 should be checked with `ffmpeg -filters | findstr rubberband`), Node only for the optional UI-sound package, optional YAMNet tagging (`listen.py install`), a venv for the masking model. **No GPU, no API key.** Windows notes in the README: `winget install Python.Python.3.12`, `winget install Gyan.FFmpeg`, skill folder at `%USERPROFILE%\.claude\skills\real-sfx`, `PYTHONUTF8=1` for non-Latin paths, and "In PowerShell, quotes break JSON arguments: put them in a file."
- **Windows install (do not run yet)**:
  ```
  git clone https://github.com/Clipwing/skills.git C:\tools\clipwing-skills
  xcopy /E /I C:\tools\clipwing-skills\skills\real-sfx %USERPROFILE%\.claude\skills\real-sfx
  cd %USERPROFILE%\.claude\skills\real-sfx
  python scripts\setup.py init --library main="D:\Sounds\SFX" --uisfx --index
  python scripts\setup.py check
  ```
  then restart Claude Code. Or install the packaged `.skill` file in the Claude app ("Save skill").
- **How it plugs into our pipeline**: our EDL is already a cue list. A 30-line converter writes `docs/cues.json` with `{"t": frame/fps, "type": "whoosh"}` per cut and `{"t": start/fps, "type": "pop"|"tick"|"click"}` per overlay start from the props JSON, plus `{"t": ..., "type": "typing", "len": ..., "n": ...}` for any type-on caption. Then `from_cues.py docs/cues.json --video reel.mp4 --out work/cues.json`, `mix.py work/cues.json --out result/reel_sfx.mp4 --voice-safe --duck`, `critique.py`. The output WAV goes back into our ffmpeg mux so our own loudness pass stays last. We never need the picture-scan path.
- **Judgment**: **worth installing the scripts; do not adopt the agent loop.** It is heavy (evals, references, a Russian/English SKILL.md that expects Claude to drive it to an 8/10 critique score), but `from_cues.py` + `mix.py` + the 78 CC0 UI cues are exactly the missing piece: typed cues in, frame-placed real sounds and a separate stem out, with voice-safe ducking and beat snapping built in. It also needs a library we own; see 2.3 and the alternatives. Watch-outs: Windows path and quoting caveats are stated by the author, and the pitch-to-music feature needs ffmpeg's rubberband.
- **Alternatives**: **reel-sfx** again (same cue-in, stem-out idea in 200 lines, CC0 sounds included, no library needed, but only 19 sounds and no ducking subtleties). **Our own `place_sfx.py`** over ffmpeg `adelay` + `amix` (we already have the timings; the only things real-sfx adds that are hard to write are beat snapping and the masking critique). **earshot `kit` + `timeline`** (synthesised instead of recorded, but the lock file gives the peaks and `timeline --cues` audits the sync).

### 2.3 Openverse API

- **What it is**: `https://api.openverse.org/v1/audio/`, the WordPress Foundation's search API over openly licensed media (API code MIT). Audio stats on 2026-11-21: **Wikimedia Commons 4,004,378, Jamendo 644,709, Freesound 591,899**, so about **5.24M audio records**, which is where his "5,000,000+ SOUNDS" counter comes from. Reality check: the Wikimedia share is mostly speech, pronunciations and music; **the sound-effect hits are Freesound's**, so Openverse is a key-free front door to Freesound's CC0 subset. `q=whoosh&license=cc0` returns 240 results today.
- **No install.** A GET with no key works: anonymous limits observed in the response headers today are **20 requests per minute burst and 200 per day sustained**. Registering (`POST /v1/auth_tokens/register/` with a unique `name`, `description`, `email`; verify the email; then `POST /v1/auth_tokens/token/` client_credentials; send `Authorization: Bearer ...`) gives "slightly higher" limits and larger pages; the exact numbers are not published in the schema ("Contact Openverse if you need a higher rate limit"). Pagination depth is capped for everyone (top results only, "not for exhaustive search or bulk download"). Licence filter values: `cc0`, `pdm`, `by`, `by-sa`, `by-nc`, `by-nd`, `by-nc-sa`, `by-nc-nd`, or `license_type=commercial,modification`. Other params: `source`, `excluded_source`, `tags`, `title`, `creator`, `category` (sound_effect, music, audiobook, podcast, news, pronunciation), `length` (shortest under 30 s, short, medium, long), `extension`, `filter_dead`, `mature`, `page`, `page_size`.
- **Response fields that matter**: `url` (a direct 128 kbps mp3 preview on Freesound's CDN, downloadable without any key), `alt_files` (the original WAV via `freesound.org/apiv2/sounds/<id>/download/`, which needs a Freesound OAuth2 token, so the WAV path means a Freesound account anyway), `license`, `license_url`, `attribution` (a ready-made credit string), `creator`, `creator_url`, `foreign_landing_url`, `duration` in ms, `filesize`, `tags`, `waveform` and `related` endpoints.
- **Terms** (docs.openverse.org/terms_of_service.html): anyone may use it; Openverse **does not verify licences** ("You are responsible for confirming your right to use any content"); provide attribution for CC works; products built on it must say they were made using Openverse and are not endorsed by it; no scraping, no multi-machine rate-limit evasion; fees possible for heavy commercial use. For us: CC0 needs no credit; CC BY needs the creator in the caption, so filter `license=cc0` and keep a `credits.txt` from the `attribution` field anyway.
- **How it plugs into our pipeline**: a 40-line Python fetcher, `fetch_sfx.py "whoosh" --cc0 --max 10 --out VIDEO/tools/sfx/whoosh/`, that calls the API, filters `duration` between 200 and 2,000 ms, downloads the preview mp3s, converts to 48 kHz wav with ffmpeg, writes `credits.txt`. Run it once per sound family (whoosh, hit, tick, click, riser, paper, cash register, air ratchet, diesel start) and the folder becomes the `main` library real-sfx wants. Anonymous limits (200 a day) are plenty for that.
- **Judgment**: **use it, today, no install.** It is the cheapest way to build a licence-clean library, and the `attribution` field solves the credit bookkeeping. Two caveats: preview quality is mp3 128 kbps (fine under music in a Reel, not fine for a sting that plays alone), and Openverse's own disclaimer means we click through to the Freesound page before using anything that will sit in a sponsor reel.
- **Alternatives**: **Freesound APIv2 directly** (free key, 60 requests per minute and 2,000 per day, `filter=license:"Creative Commons 0"`, previews free, original WAV downloads need OAuth2, API terms say commercial API use is negotiated case by case but the sounds' own CC0 licence governs use of the sound; the right choice once we want WAVs). **Kenney.nl** "Interface Sounds" (100 files) and "UI Audio" (50 files), both **CC0**, one zip each, the fastest way to get clean clicks and confirms. **Sonniss GDC bundles** (multi-GB, free, commercial use without credit, strong on real-world foley). **BBC Sound Effects** (33,000 files, RemArc licence: personal, educational and research only; monetised, sponsored or advertising-funded content needs a Pro Sound Effects licence, so **out for anything with a partner logo on it**). Pixabay and Mixkit offer free commercial sound effects under their own licences via the website; Pixabay's public API covers images and video only, not verified today for audio. "sfxmint" could not be verified in today's searches; do not cite it.
