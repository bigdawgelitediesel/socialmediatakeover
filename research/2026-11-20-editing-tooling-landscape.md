# Editing tooling landscape: what gives an AI editor the highest ceiling on this box

Compiled 2026-11-20. Lane: tooling. Machine: Windows 11 Pro, i5-14500 (6P+8E, 20 threads), 32 GB, Intel UHD 770 (QuickSync, no discrete GPU). Installed today: ffmpeg 9.0.2 Gyan full build (libass, frei0r, libplacebo, vulkan, libvpl/QSV, xfade incl. xfade_opencl and xfade_vulkan, sendcmd/zmq, geq, minterpolate, vidstab, lut3d), Python 3.12.10 (faster-whisper, opencv, numpy, scenedetect, auto-editor), Node 24.18 / npm 11.16, Chrome 158, CapCut desktop 9.8. Not installed: DaVinci Resolve, Shotcut, Blender. Current renderer: OneDrive Desktop/VIDEO/tools/build_reel2.py (JSON edit list to one ffmpeg filter graph). Jacob's verdict on it: "low level editing."

The question is not "which tool is best" but "which tool lets an AI that writes code, cannot click a GUI, and has no GPU produce reels that read as pro-edited, repeatably." Judged on that, there is one clear primary, and ffmpeg stays as the plate factory underneath it.

## What the research actually settled

### 1. ffmpeg is a plate factory, not a motion-graphics engine
The stock xfade filter supports `transition=custom` with an `expr` over x, y, w, h and progress (https://ayosec.github.io/ffmpeg-filters-docs/7.1/Filters/Video/xfade.html). scriptituk/xfade-easing ports about 64 GL Transitions plus Penner easings into that expression syntax, but the stock-ffmpeg variant must run with `-filter_complex_threads 1`, loses color and textures, and on the author's Intel Mac an HD expression transition took about 1.5 minutes versus 2.5 seconds with the patched build, which has to be compiled under MSYS2 (https://github.com/scriptituk/xfade-easing). ffmpeg-gl-transition requires building ffmpeg from source with OpenGL/EGL (https://github.com/transitive-bullshit/ffmpeg-gl-transition). Our build has frei0r compiled in but no plugin directory, libplacebo takes mpv .hook shaders and .cube LUTs (https://ayosec.github.io/ffmpeg-filters-docs/8.0/Filters/Video/libplacebo.html) but there is no bloom/glow recipe in circulation and it wants a Vulkan device. ASS tags (\t, \move, \fad, \fscx, \k) cover word-pop captions, but \t animates a limited tag set and a line cannot chain two \move tags (https://aegisub.org/docs/latest/ass_tags/). Where ffmpeg still wins outright: decode/encode (h264_qsv, hevc_qsv, av1_qsv present), minterpolate slow-mo, vidstab, lut3d normalization, loudnorm, sidechain ducking, and anything that is a per-clip "plate."

### 2. Python frame compositing re-implements an engine
MoviePy's own README concedes it is slower than ffmpeg because every frame round-trips Python to numpy to ffmpeg, and its frame cache holds exactly one frame (https://www.codeline.co/thoughts/repo-review/2025/moviepy-video-editing-with-python, https://github.com/Zulko/moviepy/issues/2231). Synthetic 1080p numpy stages measure around 130 fps total for simple ops but real decode is far slower (https://theneuralbase.com/opencv/learn/advanced/throughput-measurement/), and vidgear WriteGear users report ~10 fps until the pipeline is tuned (https://github.com/abhiTronix/vidgear/issues/270). Nothing here gives easing, kerning-aware text, motion blur, or GPU blur for free. Keep OpenCV for analysis (scene cuts, frame sheets, beat/motion energy) and the odd mask, not for the composite.

### 3. Remotion is the right primary
License: free for individuals and companies of up to 3 people, all features, unlimited commercial use; Company License is $25 per seat per month (Creators) or $0.01 per render with a $100/month minimum (Automators); Enterprise from $500/month (https://www.remotion.dev/docs/license/pricing.md, https://github.com/remotion-dev/remotion/blob/main/LICENSE.md). Headcount counts all personnel of the company, so if rendering ever moves under 307 Motorsports/Elite Diesel rather than Jacob personally, budget the $25 seat. The license "will slightly change" in 5.0; re-read it then.

Ceiling: everything the Resolve short-form transcripts describe as the pro look is a few lines of React. Ryan Herrick's workflow (https://www.youtube.com/watch?v=EEV3E2U0keQ) is: J-cuts, Fusion text with a transform keyframe eased cubic-out over 20 frames, a 4-frame motion-blur trail, a soft glow, a light-leak overlay in Add/Screen blend, a punch-in zoom on the cut, captions in one clean font, a whoosh or riser under every movement. Resolve Cut's intermediate edit (https://www.youtube.com/watch?v=T3P3r4cOJN8) adds the 9-frame adjustment-layer slide transition with duplicated edges, staggered 5-frame image reveals, and a highlighter bar revealed with crop keyframes. In Remotion those map to `interpolate`/`spring` with `Easing.out(Easing.cubic)`, `@remotion/motion-blur` (Trail, CameraMotionBlur), CSS `text-shadow`/`filter: blur()`, `mix-blend-mode: screen`, `clip-path` keyframes, and `@remotion/transitions` TransitionSeries (fade, slide, wipe, flip, clock-wipe, iris, custom presentations) (https://www.remotion.dev/docs/transitions/presentations). Captions: `@remotion/captions` builds TikTok-style pages from word timestamps, which our faster-whisper JSON already provides.

Footage: the docs now say use `<Video>` from `@remotion/media` (Mediabunny/WebCodecs frame extraction) and that `<OffthreadVideo>` and `<Html5Video>` are "not optimized" (https://www.remotion.dev/docs/performance, https://www.remotion.dev/docs/media/video). The known footage slowdown is long-GOP sources, where ffmpeg has to decode a large chunk to reach one frame; re-encoding the source fixes it (https://github.com/orgs/remotion-dev/discussions/3070). That is exactly why the ffmpeg plate pass should write short-GOP intermediates.

Speed: no clean public benchmark exists for 1080x1920 footage on a CPU like this; third-party guides quote 1 to 5 minutes per minute of video locally (https://www.pkgpulse.com/guides/remotion-vs-motion-canvas-vs-revideo-programmatic-video-2026). Remotion's own guidance is to run `npx remotion benchmark` to pick concurrency; more Chromium tabs is not always faster (https://github.com/remotion-dev/remotion/issues/4949). Hardware encode is NVENC-only on Windows, QuickSync is not supported, so the final H.264 stays on x264 or we hand frames to our own ffmpeg (https://www.remotion.dev/docs/hardware-acceleration). GPU-flavoured CSS (blur, box-shadow, gradients) is flagged as a cloud bottleneck because cloud boxes have no GPU; this box has an iGPU and Remotion reports SwiftShader unless `--gl=angle` is set, and the two paths draw slightly different pixels (https://github.com/remotion-dev/remotion/issues/13043). Set `--gl=angle` and test.

Stability: pin versions. 4.0.540 with Chrome Headless Shell 158 stopped rendering deterministically on Windows 11 where 4.0.539/Chrome 157 was deterministic (https://github.com/remotion-dev/remotion/issues/12929); a browser crash mid-render can hang parallel encoding (https://github.com/remotion-dev/remotion/issues/12840); HTML-in-canvas transitions between two OffthreadVideo scenes crashed on Chrome 157 (https://github.com/remotion-dev/remotion/issues/12470); a `.cmd` browserExecutable fails on Node 24. The docs say never set `--chrome-executable`, run `npx remotion browser ensure` first, and use `--log=verbose` (https://www.remotion.dev/docs/cli/render). Remotion publishes an official agent skill for Claude Code (`npx skills add remotion-dev/skills`) with rule files for captions, media, timing and transitions (https://mcpmarket.com/tools/skills/official/remotion-dev), which is the lowest learning curve of any option here. Motion Canvas and Revideo are MIT and faster for pure vector scenes, but canvas-only and weaker with footage (https://v3.remotion.dev/docs/compare/motion-canvas, https://news.ycombinator.com/item?id=41114294).

### 4. Resolve: the free door closed in September
Blackmagic moved Python scripting to Studio in 21.1 (8 Sept 2026) because "the Python API was being used to hack studio features into the free version"; Free 21.1 silently ignores .py scripts, sandboxed Lua still runs from the Scripts menu (can add render jobs, append clips, touch Fusion comps, but no file I/O, no os.execute, no print), and external scripting from another process was Studio-only before and still is (https://xere.my/journal/davinci-resolve-21-1-free-python-scripting-removed-lua-benchmark/, https://agentcut.dev/blog/resolve-free-21-1-python-scripts-missing/, https://www.cined.com/davinci-resolve-21-1-released-ai-assistant-integration-via-mcp-individual-hdr-trims-and-python-scripting-moves-to-studio/). Studio ($295 one-time) restores the full API plus a native MCP server under File > Setup AI Assistants that detects Claude Code (https://ymcinema.com/2026/09/17/davinci-resolve-21-1-mcp-ai-assistants-control-edit/). Even then Resolve has to be open with the GUI, timeline state lives in its database, Fusion on a UHD 770 is slow, and an AI driving it is driving a 4,000-page application through a side door. Verdict: not for Claude. If Jacob himself wants to learn an NLE, Resolve is where the pro short-form editors in the transcripts live, and Claude could hand him FCPXML/OTIO timelines, LUTs and caption files to import. Park the $295 until he asks.

### 5. MLT is the honourable second
melt.exe ships inside Shotcut and renders Shotcut XML directly (`melt project.mlt -consumer avformat:out.mp4`) (https://forum.shotcut.org/t/export-at-the-command-line/44067). MLT 7.22 added true eased keyframes (sinusoidal, quadratic, elastic, bounce, plus three Catmull-Rom smooth modes) to its animation strings (https://www.mltframework.org/blog/v7.22.0_released/, https://www.mltframework.org/docs/propertyanimation/). That gives eased transforms without expression gymnastics, but text animation and glow are still bolt-ons, docs are thin, and the quality ceiling sits below Remotion. Blender VSE renders on one core (https://github.com/jmtscaff/pulverize), Natron is a compositor with a headless renderer and 2.6 community builds (https://github.com/Niik-l/Natron/releases/tag/natron-2.6-2026.10.30), Olive is stalled (https://www.blog.brightcoding.dev/2026/07/19/olive-editorolive-open-source-node-based-video-editor-for-developers).

### 6. Commercial render APIs
Shotstack is cheapest (about $0.20/min PAYG, plans $39 to $499), JSON2Video sits in the middle ($16.95 hobby, $49.95 for 200 min), Creatomate is template-rich but $45 to $54/mo entry and roughly $0.84 per 1080p minute at that tier (https://www.wireflow.ai/blog/creatomate-pricing, https://www.wireflow.ai/blog/json2video-pricing). Plainly renders real After Effects templates from $69/mo for 50 minutes (https://www.plainlyvideos.com/blog/best-video-editing-api). Bannerbear is short templated MP4s from about $49/mo. Descript's API is limited and seat-priced; Runway is a generation API at about $0.05 to $0.12 per second (https://apiframe.ai/guides/runway-api-guide). CapCut has no official API, its terms forbid automated interaction, and the open-source draft generators break with app updates (https://www.wireflow.ai/blog/capcut-api, https://github.com/renezander030/capcut-cli). For 3 to 5 reels a week on a machine that can render locally, none of these buy anything Remotion does not, and all of them add an upload step and a bill.

### 7. What high-output shops actually run
Three tiers. Faceless automation: n8n orchestrating an LLM, TTS, stock footage and a renderer (JSON2Video, Shotstack, Remotion or raw ffmpeg); output is uniform stock-plus-captions and the community's own threads complain about jittery ffmpeg zoompan (https://dev.to/ehmad_fromqluedental_a1/faceless-video-automation-in-n8n-outline-costs-limits-3c43, https://community.n8n.io/t/fully-autonomous-ai-animation-studio-solving-character-consistency-ffmpeg-jitter/291814). Talking-head clipping: OpusClip first, Submagic for caption styling and b-roll, then post; reviewers rate Opus best for extraction but shallow for craft (https://www.youtube.com/watch?v=OHODMrUZlpo, https://www.conbersa.ai/learn/capcut-vs-opusclip). Premium short-form: Premiere/After Effects MOGRTs or Resolve with purchased asset packs, power bins and Fusion macros, which is Ryan Herrick's 633k-view workflow. Jacob's lane (car-build and car-edit footage with speed ramps and minimal text) is the third tier, and the third tier is exactly a component library of reusable animations, which is what a Remotion repo is.

## Recommendation

Primary stack: Remotion 4.x project in the VIDEO tools folder, fed by the same JSON edit list build_reel2.py uses today (as inputProps), rendering 1080x1920 30 fps H.264 on CPU, with Remotion Studio available for Jacob to scrub a preview and `npx remotion still` so Claude can inspect its own frames.

Stays in ffmpeg (Python wrapper): ingest and normalize to short-GOP 1080x1920 CFR plates; speed ramps and minterpolate slow-mo; vidstab; lut3d grade normalization; auto-editor silence cuts and scene detection; audio bed, sidechain ducking, loudnorm to -14 LUFS; final mux and, when speed matters, a QuickSync re-encode. Keep build_reel2.py alive as "fast mode" for memes and same-day posts.

Jacob in CapCut: trending audio (the API path can never apply licensed sound), the final eyeball, and any velocity-edit or template polish he enjoys doing by hand. Target: under five minutes of CapCut per reel.

## Migration plan (this Windows box)

1. Scaffold: `cd "%OneDrive%\Desktop\VIDEO\tools" && npx create-video@latest rival-reels --template blank` (TypeScript). Add `@remotion/media @remotion/transitions @remotion/captions @remotion/motion-blur @remotion/google-fonts @remotion/layout-utils`. Commit a lockfile and pin `remotion` and all `@remotion/*` to one version (start on 4.0.539 if 158 determinism bites).
2. Browser: `npx remotion browser ensure`. Never set `--chrome-executable`. Add `--gl=angle` to the render config and compare one still against the SwiftShader default.
3. Benchmark: `npx remotion benchmark --concurrency=4,6,8,10` on a 30 s composition with two real plates; lock the winner into remotion.config.ts.
4. Bridge: `src/RivalReel.tsx` reads the existing edit-list JSON (shots, in/out, transitions, captions, overlays, audio) via `calculateMetadata` for duration; `--props=edit.json` at render time. No second schema.
5. Plate pass: `tools/plates.py` runs ffmpeg per shot: 1080x1920 crop, 30 fps CFR, `-c:v libx264 -crf 14 -g 15 -bf 0 -pix_fmt yuv420p`, audio to WAV; optional minterpolate, vidstab, lut3d here.
6. Captions: convert faster-whisper word JSON to Remotion `Caption[]`, page with `createTikTokStyleCaptions`, one brand font, active-word highlight with a spring pop.
7. Motion kit v1: hook title (cubic-out, 4-frame Trail), punch-in with CameraMotionBlur, highlighter underline (clip-path), screen-blend light leak, number counter, lower-third; three transitions (push with duplicated edges, zoom-blur dissolve, iris). Each one auto-attaches a whoosh/riser from the SFX folder.
8. Render: `npx remotion render RivalReel out\reel.mp4 --props=edit.json --codec=h264 --crf=18 --log=verbose`, then `ffmpeg -i reel.mp4 -i bed.wav ... loudnorm` for the final. QA: `npx remotion still` at hook, each transition and the CTA, plus the existing frame-sheet script.
9. Skill: `npx skills add remotion-dev/skills --skill remotion-best-practices` into the repo so every session loads the official rules.
10. Preview for Jacob: `npx remotion studio` when he wants to scrub; otherwise he gets the MP4 and a no-captions MP4 as today.

## Risks

Version churn on Windows (determinism, crash hangs, canvas-transition crashes): mitigated by pinning and a smoke-render before each session. CPU render time with no discrete GPU: mitigated by plates, tuned concurrency, and keeping reels under 60 s; measure before promising. License drift: free today for Jacob as an individual; if 307 with more than three staff becomes the user, pay the $25 seat. "Template look": the faceless tier proves motion graphics can make footage look cheaper; the mitigation is restraint rules from the craft transcripts (one font, one accent colour, eased cubic-out, 4-frame blur, SFX on every move, text only when it adds information). Remotion 5.0 license wording change: re-read on upgrade. Remotion's audio mixing is fine but loudness compliance stays in ffmpeg.
